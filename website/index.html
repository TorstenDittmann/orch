orch source

Application orchestration for small Linux clusters.

orch runs applications across 1–20 Linux nodes. It provides typed configuration, scheduling, health checks, service discovery, private networking, ingress, cron jobs, and safe rollouts without exposing the Kubernetes or Docker Swarm APIs. 

$ orch deploy -f orch.pkl --target production

Configuration

Applications are typed Pkl modules. Unknown fields are errors and defaults resolve before planning.

amends "orch:/v1alpha1/Application.pkl"

name = "api"

services {
  ["web"] {
    image = "ghcr.io/acme/api@sha256:…"
    replicas = 2
    dependsOn { "redis" }
    http = new Http {
      port = 8080
      public = true
      healthPath = "/healthz"
    }
  }

  ["redis"] {
    image = "docker.io/redis@sha256:…"
    tcp = new Tcp { port = 6379 }
  }
}

deploy {
  maxSurge = 1
  autoRollback = true
}

Included

  • Runtime: OCI images on containerd and runc.
  • Placement: resource requests, labels, dependencies, and local volumes.
  • Network: service DNS and a managed WireGuard mesh.
  • Ingress: readiness-aware HTTP, HTTPS, and raw TCP routes.
  • Jobs: scheduled cron jobs with retained run history.
  • Operations: CLI and TUI over direct, WireGuard, or SSH targets.
  • Visibility: runtime inventory, events, and live stdout/stderr logs.

Architecture

A controller stores desired state and computes placement. Agents reconcile workloads on each node and keep running during controller outages. The controller is not in the application data path.

Scope

orch is in early development. It targets small teams operating a handful of mutually reachable Linux VMs. It is not a Kubernetes-compatible API, a general-purpose platform, or a hosted control plane.
