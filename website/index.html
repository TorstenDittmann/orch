Work in progress

Orchestration for small Linux clusters.

orch runs applications across 1–20 nodes. It provides typed configuration, scheduling, health checks, service discovery, private networking, HTTP and TCP ingress, cron jobs, and safe rollouts—without exposing the Kubernetes or Docker Swarm APIs.

$orch deploy -f orch.pkl --target production

Configuration

One typed Pkl module.

Unknown fields are errors. Defaults resolve before planning. Local and HTTPS modules compose without sending source code to the cluster.

orch.pklPKL
amends "orch:/v1alpha1/Application.pkl"

name = "api"

services {
  ["web"] {
    image = "ghcr.io/acme/api@sha256:…"
    replicas = 2
    dependsOn { "redis" }
    http = new Http {
      port = 8080
      public = true
      healthPath = "/healthz"
    }
  }

  ["redis"] {
    image = "docker.io/redis@sha256:…"
    tcp = new Tcp { port = 6379 }
  }
}

deploy {
  maxSurge = 1
  autoRollback = true
}

Network
Service DNS and a managed WireGuard mesh
Ingress
Readiness-aware HTTP, HTTPS, and raw TCP routes
Operations
CLI and keyboard-first TUI over direct, WireGuard, or SSH targets
Observability
Runtime inventory, events, and live stdout/stderr logs

Model

01

Describe

Validate and plan the resolved application locally.

02

Deploy

The controller places work and coordinates health-gated rollouts.

03

Operate

Agents keep workloads running when the controller is unavailable.

Scope

Built for small engineering teams operating a handful of mutually reachable Linux VMs. Not intended to be a Kubernetes-compatible API, a general-purpose platform, or a hosted control plane.
